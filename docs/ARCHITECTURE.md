# Architecture

## Data model (Akoma Ntoso inspired, simplified)

* **Work**: an instrument as an abstract thing: `work_id` (e.g. `ae/fdl/2021/33`), `instrument_type` (law, decree-law, executive regulation, cabinet resolution), `title_ar`, `title_en?`.
* **Expression**: the text of a work valid over a period: `expression_id`, `work_id`, `valid_from`, `valid_to?`, `effective_date_status` (`known` | `uncertain` | `unknown`), `language`, `source_url`, `retrieved_at`, `content_sha256`, `synthetic` flag.
* **Provision**: structural node: `eid` (stable id like `art_5_bis`), `kind` (part, chapter, article, clause), `number`, `suffix`, `parent_eid`, `text_original`, `text_norm`.
* **Amendment event**: `amending_work_id`, `target_work_id`, `operations[]` (`replace`, `insert_after`, `repeal`, `renumber`, `unresolved`), `issue_date`, `gazette_date?`, `effective_date?`, `effective_date_status`.
* **Alignment**: pair `(provision_a, provision_b, score, method, confidence)` or an entry in the `unaligned` bucket.
* **Change**: classified diff: `inserted`, `replaced`, `repealed`, `renumbered`, `clarified`, with word level spans and a link to the amendment event.

Every provision row carries `source_url` and `retrieved_at` (non null; enforced by schema validation).

## Pipeline

ingest → snapshot (hash, headers, robots decision) → parse (structure + normalization) → align → diff/classify → temporal reconstruct → validate → export (SQLite → Parquet) → API → UI.

## Stack and justification

| Choice | Why |
|---|---|
| Python 3.13, stdlib first core | No heavy deps in the logic that must be auditable; `difflib`, `unicodedata`, `sqlite3` suffice |
| SQLite | One file, zero ops, easy deploy; Parquet export for the dataset |
| FastAPI | Typed read only API with OpenAPI docs |
| Static front end (vanilla JS, no build) | RTL first, fast, deployable on Vercel/Render static hosting |
| pytest + GitHub Actions | CI badge, reproducible from clean clone |

## Alignment method (M3)

v1 (`align.py`, hash locked): score = 0.85 x normalised text similarity (character trigram Jaccard and token sequence ratio) + 0.10 x relative position + 0.05 x number equality. Monotonic assignment via dynamic programming. Pairs below a threshold go to `unaligned`; pairs between thresholds, or with a close rival, are low confidence. v2 (`align_v2.py`, separate module, not the default) adds number offset evidence from anchor pairs and abstention; see `docs/PREDICTIONS_V2.md`. Thresholds and weights were tuned on synthetic development seeds only; no gold set exists yet, so they are not calibrated on real text (see `VALIDATION.md`).

## Validation (M6)

Metrics: alignment accuracy, per class diff precision/recall, point in time correctness. Gold set must be hand checked against official text with each item cited. **Blocked on text permission** (see `DATA_SOURCES.md`). Fallback: (a) synthetic gold set generated by applying known operations to synthetic base text, labeled synthetic, measuring engine correctness but **not** real world accuracy; (b) a small hand checked real set once permission or a permitted source exists. Reports must say which numbers come from which set.

## Safety constraints in code

* Fetcher refuses hosts not marked `permitted` in `sources.toml`.
* Robots.txt checked per host; minimum delay enforced.
* UI and README carry the not legal advice banner; every provision links to source with retrieval date.
