# PDF extraction (synthetic-only validation)

Module: `src/taadeel/extract_pdf.py`. Test data: `src/taadeel/synthetic_pdf.py`. Every generated PDF is stamped
`SYNTHETIC TEST DOCUMENT - NOT LEGISLATION` (visible banner and PDF metadata). Text is random pool words, not law.

## Method

1. `pypdf` per page, `extraction_mode="layout"` (bidi aware; plain mode returned character reversed words on the same files).
2. Strip bidi/format marks and soft hyphens.
3. Visual order detection (`detect_reversed`): document level vote of forward evidence (marker words such as
   المادة, tokens starting with ال) against reversed evidence (reversed marker words, tokens ending in لا). Reversed
   iff reversed evidence is strictly greater. If so, each Arabic bearing line is reversed character wise, embedded
   digit/Latin runs are re-reversed, and mirrored brackets swapped. Reversal happens BEFORE NFKC, because a lam alef
   ligature glyph expands under NFKC already in logical order. The result is reported as `reversed_detected`.
4. NFKC fold of presentation forms to base letters.
5. Header/footer removal: lines in the top/bottom 3 lines of a page that repeat (digits masked) on >= 60% of pages
   (needs >= 2 pages); lone page number lines (`5`, `- 5 -`, `صفحة ٥`, `page 5 of 9`) in the top/bottom 2 lines.
   Article, part and chapter headings are never stripped.
6. Latin hyphenation joins (Arabic is not hyphenated; lines are otherwise kept and `parse_structure` joins them).
7. No text layer at all: `needs_ocr=True`, warning `needs OCR`, empty provisions. No OCR is implemented.

`extract_expression(path, expr_meta)` then calls `parse_structure` and `validate_expression`
(`expr_meta` needs work_id, expression_id, source_url, retrieved_at; `synthetic=True` needs a `synthetic/` work_id).

## Known failures and limitations

- `mixed` layout (Latin/digit runs such as `ISO 9001`, `No. 45`, `(12)` inside Arabic sentences): text exact match is
  0.562 (9 of 16 articles); numbers still found. Runs at line starts or adjacent runs change position or order. Marked
  `xfail` in the tests, not loosened.
- All reversal logic is whole document: documents mixing logical and visual order pages are unsupported.
- Header/footer removal needs >= 2 pages; a one page document with a free text footer would leak it into the last article.
- Only one rendering stack was tested (DejaVu Sans, arabic-reshaper + python-bidi, fpdf2). Real PDFs (Word, InDesign,
  government print workflows, custom fonts without ToUnicode, tables, two columns, footnotes) are UNVALIDATED.
- Scanned/image-only PDFs are only detected (`needs OCR`); there is no OCR. A scan with a poor OCR text layer is not detected.
- Corrupt or encrypted (password) PDFs raise or warn; not scored.
- Layout mode relies on pypdf behavior (6.20.0); other pypdf versions may order RTL text differently.
